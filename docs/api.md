Every public declaration of the package, by module, with its comment from the source.

## `<ar>`

`<ar>`: augmented reality for apps on eskiu-lang/ui, over ARKit on iOS and ARCore on
Android. use_ar_session runs a world-tracking session while its scope is mounted and hands
each new frame to Eskiu on the UI thread: the camera picture as YUV planes (the layout of
ui-camera's CameraFrame, which eskiu-gpu's `<gpu/yuv>` draws), the camera's pose and
intrinsics, planes, anchors, feature points, the light estimate and depth. The geometry
(view, projection, display transform, hit-test ray) is computed in `<ar/math>`, the same on
both platforms. The web has no AR in this version (ArUnsupported).

### ArStatus

```eskiu
enum ArStatus { ArStarting, ArRunning, ArUnsupported, ArDenied, ArInstalling, ArFailed, ArPaused }
```

Where the session is: starting (asking for the camera, installing ARCore), running, or
why it is not: the device has no AR (or it is the simulator, or the browser), the camera
permission is denied, ARCore is being installed (the session starts when it is), it
failed, or it is paused while the app is in the background.

### ArTracking

```eskiu
enum ArTracking { ArTrackingNone, ArTrackingLimited, ArTrackingNormal }
```

How well the camera is tracked: not at all (its pose means nothing), limited (the pose is
rough; `reason` says why), or normal.

### ArReason

```eskiu
enum ArReason {
    ArReasonNone,
    ArReasonInitializing,
    ArReasonExcessiveMotion,
    ArReasonInsufficientFeatures,
    ArReasonInsufficientLight,
    ArReasonRelocalizing,
    ArReasonCameraUnavailable,
    ArReasonBadState
}
```

Why tracking is limited: none, starting up, the device moves too fast, too few features
(a blank wall), too dark, finding its place again after an interruption, the camera is
unavailable, or an internal error.

### ArAlignment

```eskiu
enum ArAlignment { ArHorizontalUp, ArHorizontalDown, ArVertical }
```

Which way a plane faces: horizontal facing up (a floor, a table), horizontal facing down
(a ceiling), or vertical (a wall).

### ArDepthFormat

```eskiu
enum ArDepthFormat { ArDepthMeters32, ArDepthMillimeters16 }
```

What a depth image holds: 32-bit floats in meters (ARKit's LiDAR) or 16-bit unsigned
millimeters (ARCore).

### AR_HIT_PLANES, AR_HIT_ESTIMATED

```eskiu
const int AR_HIT_PLANES = 1;
const int AR_HIT_ESTIMATED = 2;
```

Hit-test targets, combined with |: planes found so far (inside their outline), and
estimates (ARKit's estimated planes, ARCore's feature and depth points).

### AR_HIT_PLANE, AR_HIT_ESTIMATE

```eskiu
const int AR_HIT_PLANE = 1;
const int AR_HIT_ESTIMATE = 2;
```

Hit kinds in ArHit.kind.

### ArOptions

```eskiu
struct ArOptions {
    bool horizontal = true;
    bool vertical = false;
    bool light = true;
    bool light_hdr = false;
    bool depth = false;
    bool points = false;
    int image_width = 1280;
    int image_height = 720;
}
```

What use_ar_session asks for: plane detection (horizontal, vertical), the light estimate
(`light_hdr` asks ARCore for its environmental HDR estimate instead: main light and
spherical harmonics; iOS ignores it), depth where the device has it (LiDAR on iOS, the
Depth API on Android), the feature points, and the size of the camera picture (a wish: the
platform gives the nearest it has, as the sensor sees it, landscape).

### ArImagePlane

```eskiu
struct ArImagePlane { *uint8 data; int row_stride; int pixel_stride; int64 size; }
```

One plane of the camera picture: `data` (borrowed for the handler's call), the bytes from
one row to the next, from one sample to the next in a row, and the bytes readable from
`data`. The layout of ui-camera's CameraPlane and eskiu-gpu's GpuYuvPlane.

### ArCameraImage

```eskiu
struct ArCameraImage {
    int width;
    int height;
    int format;
    int plane_count;
    ArImagePlane[3] planes;
    int rotation;
    int64 timestamp_ns;
    bool front;
    int matrix;
    bool full_range;
}
```

The camera picture, with the field layout of ui-camera's CameraFrame and eskiu-gpu's
GpuYuvImage, so `(*GpuYuvImage)&frame.image` uploads it: size, format (0 NV12 on iOS, 0
NV12, 1 NV21, 2 I420 or 3 three-plane YUV on Android), the planes, how far to turn it
clockwise to be upright on the screen, the capture time, and its YUV matrix (0 BT.601)
and range.

### ArPlane

```eskiu
struct ArPlane {
    int64 id;
    int alignment;
    int tracking;
    ArMat4 pose;
    float extent_x;
    float extent_z;
    *ArVec2 polygon;
    int polygon_count;
    int64 subsumed_by;
}
```

A detected plane: an id that stays the same while it is tracked, its alignment, how well
it is tracked, its center pose (y along the plane's normal), its size along the pose's x
and z, its outline (`polygon_count` points in the pose's x-z plane, borrowed for the
handler's call), and the id of the plane that took it over (0 while it stands alone).

### ArAnchor

```eskiu
struct ArAnchor { int64 id; int tracking; ArMat4 pose; }
```

An anchor the app added: its id, how well it is tracked, and its pose, which the session
updates as it learns more about the world.

### ArPoint

```eskiu
struct ArPoint { ArVec3 position; float confidence; }
```

A feature point in world space and the platform's confidence in it (0 to 1; 1 on iOS).

### ArLightSource

```eskiu
enum ArLightSource { ArLightNone, ArLightARKit, ArLightARCore, ArLightARCoreHdr, ArLightWebXR }
```

Where a light estimate comes from: none, ARKit (ambient intensity in lumens and a color
temperature), ARCore's ambient intensity mode (pixel intensity and color correction in
gamma space), ARCore's environmental HDR mode, or WebXR's light probe.

### ArLight

```eskiu
struct ArLight {
    bool valid;
    float intensity;
    float temperature;
    ArVec3 color;
    bool has_main;
    ArVec3 main_direction;
    ArVec3 main_intensity;
    bool has_harmonics;
    float[27] harmonics;
    float raw_intensity;
    int source;
}
```

The light estimate, on one scale on every platform. `intensity` is a linear multiplier,
1.0 in a neutral scene: ARKit's ambient intensity over 1000 (its neutral), ARCore's pixel
intensity taken to linear space and over middle gray (ar_light_from_arcore). `color` is a
linear RGB tint to multiply lighting by, green 1 on ARCore (its color correction, taken to
linear space), from `temperature` (kelvin, ARKit; 6500 elsewhere) on iOS. `raw_intensity`
is the platform's own value (lumens, or ARCore's gamma pixel intensity) and `source` says
which (an ArLightSource). With ARCore's environmental HDR mode (and WebXR's light probe)
`intensity` is 1.0 and the light is the main light's direction (toward the light) and
linear RGB intensity, and 9 RGB spherical harmonics coefficients of the ambient light, in
the platform's order and scale.

### ArDepth

```eskiu
struct ArDepth { int width; int height; int format; int row_stride; *uint8 data; int64 size; }
```

A depth image, aligned with the camera picture (as the sensor gives it, often smaller):
size, format (ArDepthFormat), the bytes from one row to the next, and `data`, borrowed for
the handler's call (null when there is no depth).

### ArHit

```eskiu
struct ArHit { float distance; int kind; int64 plane; ArMat4 pose; }
```

One hit-test result: the distance from the camera, the kind (AR_HIT_PLANE or
AR_HIT_ESTIMATE), the plane hit (0 for an estimate) and the pose of the hit (y along the
surface's normal).

### ArFrame

```eskiu
struct ArFrame {
    ArCameraImage image;
    ArMat4 camera;
    ArIntrinsics intrinsics;
    int tracking;
    int reason;
    *ArPlane planes;
    int plane_count;
    *ArAnchor anchors;
    int anchor_count;
    *ArPoint points;
    int point_count;
    ArLight light;
    ArDepth depth;
}
```

A frame of the session, borrowed for the handler's call. `image` is the camera picture.
`camera` is the camera's pose (camera to world, axes along the picture as the sensor gives
it), `intrinsics` the picture's, `tracking` and `reason` how well it is tracked. Planes,
anchors and points are arrays of `*_count` items (planes and points only when the options
asked for them); `light` and `depth` are set when asked for and available.

### AR_PLANE_INFO

```eskiu
const int AR_PLANE_INFO = 22;
```

A plane: id, alignment, tracking, the center pose's 16 values, extent x and z, subsumed

### AR_ANCHOR_INFO


An anchor: id, tracking, the pose's 16 values.

### AR_LIGHT_INFO

```eskiu

```

The light: valid, intensity, temperature, color r g b, has_main, direction x y z,

### AR_HIT_INFO

```eskiu
const int AR_HIT_INFO = 19;
```

A hit: distance, kind, plane id, the pose's 16 values.

### AR_DEPTH_INFO

```eskiu

```

Depth: width, height, format, row_stride, data pointer, size.

### AR_MAX_POLYGON, AR_MAX_PLANES, AR_MAX_POINTS, AR_MAX_HITS

### use_ar_session

```eskiu

```

Runs a world-tracking session while the scope is mounted, and hands `on_frame` each new
frame on the UI thread, borrowed for the call (copy what you keep). A frame that arrives
while it runs replaces the one waiting: a slow handler gets fewer, newer frames. New
options start the session again with them. One session runs at a time; mount one per
screen.

## `<ar/math>`

`<ar/math>`: the geometry of an AR frame, the same on every platform. From the camera
image's intrinsics, the camera's pose and how far the image turns to be upright, it gives
the view and projection matrices for a viewport, the display transform from the viewport
to the image, and the ray under a point of the viewport (docs/math.md). Matrices are 4x4,
column major, with the layout of eskiu-gpu's Mat4, so a pointer to one casts to the other.

### ArVec2

```eskiu
struct ArVec2 { float x; float y; }
```

A point or size in two dimensions.

### ArVec3

```eskiu
struct ArVec3 { float x; float y; float z; }
```

A point or direction in three dimensions, in meters in world space.

### ArMat4

```eskiu
struct ArMat4 { float[16] m; }
```

A 4x4 matrix in column-major order: m[c * 4 + r] is row r of column c, so the translation
is m[12], m[13], m[14]. The layout of eskiu-gpu's Mat4 and WGSL's mat4x4<f32>.

### ArAffine

```eskiu
struct ArAffine { float a; float b; float c; float d; float tx; float ty; }
```

A 2D affine transform: (x, y) becomes (a * x + c * y + tx, b * x + d * y + ty), the
convention of Core Graphics' CGAffineTransform.

### ArIntrinsics

```eskiu
struct ArIntrinsics { float fx; float fy; float cx; float cy; int width; int height; }
```

A camera image's intrinsics, in pixels of that image as the sensor gives it: focal
lengths, principal point (from the top left corner), and the image's size.

### ArRay

```eskiu
struct ArRay { ArVec3 origin; ArVec3 direction; }
```

A ray in world space: from `origin`, along the unit vector `direction`.

### ar_mat4_identity

```eskiu
ArMat4 ar_mat4_identity()
```

The identity matrix.

### ar_mat4_mul

```eskiu
ArMat4 ar_mat4_mul(ArMat4 a, ArMat4 b)
```

a * b: b is applied first.

### ar_mat4_rigid_inverse

```eskiu
ArMat4 ar_mat4_rigid_inverse(ArMat4 m)
```

The inverse of a rigid transform (a rotation and a translation, as poses are): the
transposed rotation and the translation taken back through it.

### ar_mat4_point

```eskiu
ArVec3 ar_mat4_point(ArMat4 m, ArVec3 p)
```

The point `p` through `m` (w = 1, no division).

### ar_mat4_direction

```eskiu
ArVec3 ar_mat4_direction(ArMat4 m, ArVec3 d)
```

The direction `d` through `m`'s rotation (w = 0).

### ar_mat4_project

```eskiu
ArVec3 ar_mat4_project(ArMat4 m, ArVec3 p)
```

The point `p` through `m` (a projection times a view), divided by w: normalized device
coordinates, x and y from -1 to 1 (y up), z from 0 at the near plane to 1 at the far one.

### ar_mat4_position

```eskiu
ArVec3 ar_mat4_position(ArMat4 m)
```

The translation of `m`: a pose's position.

### ar_mat4_translation

```eskiu
ArMat4 ar_mat4_translation(ArVec3 t)
```

A translation by `t`.

### ar_mat4_rotation_z

```eskiu

```

A rotation about the z axis by `degrees`, counterclockwise looking down -z.

### ar_vec3_length

```eskiu
float ar_vec3_length(ArVec3 v)
```

The length of `v`.

### ar_vec3_normalize

```eskiu
ArVec3 ar_vec3_normalize(ArVec3 v)
```

`v` scaled to length 1 (unchanged when it is zero).

### ArIntrinsics_upright

```eskiu
ArIntrinsics ArIntrinsics_upright(*ArIntrinsics self, int rotation)
```

The intrinsics of the image once turned `rotation` degrees clockwise (0, 90, 180 or 270),

### ar_cover_scale

```eskiu
double ar_cover_scale(int upright_width, int upright_height, double width, double height)
```

How much the upright image is scaled to cover a viewport of `width` x `height` (aspect

### ArIntrinsics_view_to_image

```eskiu

```

The point (x, y) of a viewport `width` x `height` (in any unit, from the top left) as a
pixel of the image as the sensor gives it, when the image is turned `rotation` degrees
clockwise and covers the viewport.

### ArIntrinsics_display_transform

```eskiu
ArAffine ArIntrinsics_display_transform(*ArIntrinsics self, int rotation, double width, double height)
```

The display transform for a viewport `width` x `height`: from normalized viewport
coordinates (0 to 1 from the top left) to normalized image coordinates (0 to 1 of the
image as the sensor gives it), for an image turned `rotation` degrees that covers the
viewport. It is where a background shader samples the camera image.

### ArAffine_apply

```eskiu
ArVec2 ArAffine_apply(*ArAffine self, float x, float y)
```

(x, y) through the affine transform.

### ArIntrinsics_projection

```eskiu
ArMat4 ArIntrinsics_projection(*ArIntrinsics self, int rotation, double width, double height, double near, double far)
```

The projection for a viewport `width` x `height`: a camera with the image's intrinsics,

### ar_view_matrix

```eskiu
ArMat4 ar_view_matrix(ArMat4 camera, int rotation)
```

The view matrix (world to camera) for a camera whose pose `camera` (camera to world, x
right and y up along the image as the sensor gives it) is shown turned `rotation` degrees
clockwise: x right and y up as the screen shows the picture.

### ArIntrinsics_ray

```eskiu
ArRay ArIntrinsics_ray(*ArIntrinsics self, ArMat4 camera, int rotation, double width, double height, double x, double y)
```

The ray from the camera through the point (x, y) of a viewport `width` x `height` (from
the top left) that the image covers turned `rotation` degrees.

### ArIntrinsics_world_to_image

```eskiu
ArVec3 ArIntrinsics_world_to_image(*ArIntrinsics self, ArMat4 camera, ArVec3 p)
```

The pixel of the image (as the sensor gives it) where the world point `p` appears, for a
camera at pose `camera`; z is the distance in front of the camera (negative behind it).

### ar_light_from_arkit

```eskiu
float ar_light_from_arkit(double lumens)
```

The light estimate's scale, the same on every platform: a linear multiplier of the light,
1.0 in a neutral scene (a mid-gray world under neutral light). ARKit's ambientIntensity is
in lumens, 1000 neutral, and already linear: over 1000. ARCore's pixel intensity is the
camera view's mean in gamma space (0 to 1); Google's reference says to take it to linear
space with the power 2.2 and divide by 0.18, middle gray in linear space (0.466, middle
gray in gamma space, is the same gray: 0.466^2.2 = 0.186).

### ar_light_from_arcore

```eskiu
float ar_light_from_arcore(double pixel_intensity)
```

ARCore's pixel intensity (gamma, 0 to 1) on the light estimate's scale (see
ar_light_from_arkit): 1.0 at middle gray.

### ar_gamma_to_linear

```eskiu
float ar_gamma_to_linear(double value)
```

A gamma-space color value (ARCore's color correction) in linear space, the power 2.2 of
Google's reference.

### ar_temperature_rgb

```eskiu
ArVec3 ar_temperature_rgb(float kelvin)
```

The RGB tint of light at a color temperature in kelvin, in linear RGB, scaled so 6500 K is
white (1, 1, 1): ARKit's ambientColorTemperature as a color. Tanner Helland's fit of the
blackbody colors (gamma-space values, good to a few percent from 1000 to 40000 K), taken
to linear space with the power 2.2 like ARCore's color correction.
